# P3-2 伺服器端發布控制（候選實作）

基準 d2142df / #41。前端 P3_ADMISSION_READS_ENABLED 與 P3_ADMISSION_CREATE_ENABLED 仍 false。此 PR 在候選 firestore.rules 為 roomInvites 新建加入伺服器端關卡，利用現有原子建立不變量：新 V3 房間必須與新 invite 同時建立，因此 invite 關閉時整筆新 V3 建房失敗。舊房及既有 V3 的加入、重連、遊戲不讀取此旗標，不應因關閉新建而中斷。

管理文件路徑 rolloutControls/p3Admission；僅具適當 IAM 權限的管理端可操作，沒有授予客戶端讀寫規則。只有布林值 createEnabled:true 啟用；缺失、false、非布林值皆拒絕。此 PR 不建立正式控制文件，不部署 Rules，不改前端開關，不變更正式資料／費用。正式部署前須核對正式控制文件不存在或嚴格為 false，禁止僅以 JS 常數當作安全限制。

測試：既有 #41 91 項斷言保留，增加未設定旗標／錯誤型別／非授權讀寫／關閉後拒絕新建／既有 V3 重連及投票／舊版建房。開啟只在隔離 emulator 由測試特權上下文建立。需本 PR 最新 CI 通過並審查規則運算式與存取次數限制後才合併。

發布：先完成 P2.5 隔離金鑰及安全核准；管理者核對規則版本、App Check 與計費、控制文件及備份，部署已驗證的相容 Rules 且關閉 V3 新建；檢查舊房。再發布 READS 開啟、CREATE 關閉之相容前端，驗證。另在隔離雲端驗證 V3；正式啟用須受控切換及實機驗收。回滾先由管理端關閉新建，保留相容規則及讀取路徑直到既有 V3 房結束，不以舊 Rules 回退暴露 V3 資料。正式雲端尚未驗證。

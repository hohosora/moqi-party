# 🤪 默契失控局｜題數連動 Gemini 優化版

台灣繁體中文手機破冰遊戲，適合 10–20 人。保留原本的 6 碼房間、投票、雙倍王牌、每回合得分及即時排行榜，擴充三種出題來源，並保留答題時間 **15／30／45 秒**（預設 30 秒）。這版將「遊戲回合」改為「遊戲題數」，並將 Gemini 預設生成題數與首頁遊戲題數自動連動。

## 本次更新重點：遊戲題數與 Gemini 連動

- 首頁名稱改為 **遊戲題數**（6／8／10／12 題），遊戲中顯示「第 1／12 題」。
- 首頁選 **12 題** → 進入「管理題庫 → Gemini 生成」時，預設**要求 Gemini 產出 12 題**，不必在兩個畫面重複設定。
- Gemini 題數提供三種選法：「**依遊戲題數**」（預設）、「**多備 4 題**」、「**準備 20 題備用**」。例：首頁 12 題時，Gemini 可以產生 12、16、20 題。
- 回首頁更改遊戲題數後，Gemini 生成數量會再次同步到新的題數；額外備用題要再手動選一次。
- **仍是 Gemini 網頁生成後手動貼回遊戲**，不是網站自行呼叫 Gemini API。題目若與原有內容重複，會被跳過；純 Gemini 題庫至少需要足夠的不重複題目才能開局。
- 不變的部分：主持人自訂、初版 28 題、混合模式、15／30／45 秒、多人 Firebase 房間、積分與排行榜。

## 原有三種題庫


**① 主持人自訂**：新增／修改／刪除題目，每題 1 個問題、4 個選項、1 個開獎後聊天引導。

**② Gemini 生成**：在「管理題庫 → Gemini 生成」選擇三種方向：「最近流行話題」、「荒謬日常」、「朋友默契」，按「複製出題指令」，開啟自己的 Gemini 網頁，貼上指令生成題目，將回覆 JSON 複製回遊戲，預覽、檢查後再收藏。**不需要 API 金鑰，也沒有直接存取 Gemini 帳號。** 若選近期熱門，題目新鮮度以 Gemini 當次可取得的搜尋結果為準。

**③ 經典歷史**：保留原版 28 題，無法在題庫管理畫面中覆寫或刪除。

開局前可以選「三種混合（有新題時均衡抽題）」、「經典歷史」、「主持人自訂」或「Gemini 生成」。

## 新手第一次使用

1. 開啟遊戲頁面，輸入主持人暱稱。
2. 點「⚙️ 管理題庫」。
3. 選「主持人自訂」新增自己的四選一題，或選「Gemini 生成」照步驟把 AI 回答匯入。
4. 返回首頁，在「出題來源」選擇本次要使用的題庫。
5. 在首頁選擇 **遊戲題數：6／8／10／12 題**，Gemini 預設產生的題數會跟著設定同步。
6. 選擇答題時間：**15 秒快速挑戰／30 秒（預設推薦）／45 秒輕鬆作答**。
7. 先用「🎭 先玩示範局」測試，再用「🚀 建立多人房間」邀請其他人的手機參與。

**題目數量提醒**：純自訂／純 Gemini 模式，該題庫必須至少有與設定題數相同的不重複題目；否則頁面會要求先新增題目或減少遊戲題數。選擇「三種混合」時可使用經典題補足。

## Gemini 指令生成和匯入（無 API）

1. 開啟「管理題庫 → Gemini 生成」。
2. 選擇「🔥 最近流行話題」、「🤣 荒謬日常」或「💛 朋友默契」；**預設依首頁遊戲題數自動生成**。如需備用題，再改選多備 4 題或 20 題。
3. 按「📋 複製出題指令」，再按「↗ 開啟 Gemini 網頁」。
4. 在 Gemini 網頁貼上指令、送出，等生成完畢。
5. 複製 Gemini 的完整 JSON 回覆（可包含 ` ```json ` 程式碼區塊）。
6. 回到《默契失控局》，貼進大文字框，按「🔎 檢查題目與預覽」。
7. 預覽四個選項和聊天引導，沒問題再按「✅ 確認加入 Gemini 題庫」。
8. 回到首頁，選「Gemini 生成」或「三種混合」開局。

匯入的最小格式：

```json
[
  {
    "q": "如果你每天都收到一封來自未來的郵件，最可能是什麼？",
    "a": ["提醒你別再按貪睡", "預告今天午餐還是吃麵", "通知你已成為耍廢大師", "要求你趕快回家睡覺"],
    "talk": "你最想收到哪種離譜預言？"
  }
]
```

若 Gemini 回覆有前後解釋而不是 JSON，請要求它「只輸出合法 JSON 陣列，不要其他文字」，再貼回遊戲。

**內容審核**：系統會檢查 JSON 格式、四個答案及重複題目，不代表能自動判斷所有 AI 內容是否適合場合。主持人仍應先閱讀並篩掉不合適的題目。

## 自訂與 Gemini 題庫存在哪裡？

- 兩種新增題庫**僅儲存在主持人當前瀏覽器的 localStorage**，不是存到 GitHub、Firebase 共用題庫或 Gemini 帳號。
- 同一瀏覽器同一網站重開，一般仍會保留；清除網站資料、無痕模式、換電腦／手機可能遺失。
- 請在「題庫管理」底下定期按「下載題庫備份」。換裝置時可用「匯入備份檔」還原，重複題目會略過。
- 每場**開房時**會將抽中的題目快照存入 Firebase 的該房間文件，因此參與者只需加入房間，就會看到相同題目；玩到一半新增題庫不會影響既有房間。
- 目前最多保存 100 道自訂題和 100 道 Gemini 題；每次 Gemini 匯入最多 30 題。

## GitHub 升級操作（你的專案 `hohosora/moqi-party`）

**本次題數連動只需更新 `app.js` 與 `styles.css`**；`README.md` 為可選說明檔。若先前 15 秒的 Firebase 規則尚未更新，才需要額外發布 `firestore.rules`。**

1. 先到 https://github.com/hohosora/moqi-party 查看目前網站檔案。
2. 在儲存庫頂端選 `Add file` → `Upload files`，上傳新版 **`app.js`**、**`styles.css`**（可選上傳 `README.md`），檔案名稱務必一致且放根目錄。
3. 確認上傳清單顯示既有檔案已被修改／取代，而不是變成 `app (1).js` 或新子資料夾。
4. 填入 Commit message：`遊戲題數與 Gemini 生成題數自動連動`。
5. 選直接提交 `main`，按 `Commit changes`（若 GitHub 要求用 Pull Request，依頁面建立及合併）。
6. 檢查 `Settings → Pages → Build and deployment` 的來源仍為 `Deploy from a branch`、`main`、`/(root)`。如果原本已經正確，**不需要重設**。
7. 開啟 https://hohosora.github.io/moqi-party/ ，用 `Ctrl+Shift+R` 強制重新載入（手機可重新開啟網頁），確認有「**遊戲題數**」和「⚙️ 管理題庫」。選 12 題後打開 Gemini 生成，預設應顯示「**依遊戲題數：12 題（推薦）**」。

**不要上傳 ZIP 本身、不要把檔案多包進另一個資料夾，也不要用其他設定檔覆蓋現在的 `firebase-config.js`。**

### Firebase 需要改什麼？（通常不需修改）

**這次題數連動沒有變動 Firebase 資料結構與安全規則，不必重新設定 Firebase。** 但如果你先前尚未更新 15 秒計時的 Firestore Rules，請先確認 Firebase 控制台中的規則已允許 `[15,30,45]`。升級包提供相容的 `firestore.rules` 供你檢查或補救。

1. 若先前已經成功以 15 秒建立正式多人房間，這段可以全部跳過。若尚未成功，才需要確認 Firebase 規則。
2. 到 https://console.firebase.google.com/project/moqi-party/firestore/rules ，在 Firebase 控制台選擇 Firestore Database →「規則（Rules）」。
3. 在 GitHub 專案根目錄打開新版 `firestore.rules`，複製**全部文字**。
4. **僅在目前 Firestore 規則尚未支援 `[15,30,45]` 時**，先確認這份規則與目前遊戲需求相容，再在 Firebase 規則編輯器**取代原有的全部內容**，按 **Publish／發布**。確認發布成功後用 15 秒進行真實多人房間測試。
5. 不需要重新建立資料庫、變更匿名登入，也**不要修改或覆蓋**已設定的 `firebase-config.js`。

安全提醒：不要將規則改成 `allow read, write: if true;`。舊的 60 秒房間即使仍存在，也不會因新規則而自動中斷，但新的房間不再提供 60 秒選項。

## 正式測試順序

1. 首頁 → 題庫管理 → 看見經典 28 題。
2. 自訂新增 1 題，確認題目出現在列表；試著編輯，然後匯出備份。
3. **先在首頁選 12 題** → 進入 Gemini 生成，確認預設「12 題」；切換「多備 4 題」應顯示 16 題，「準備 20 題」應顯示 20 題。再試著複製指令、開 Gemini、複製 JSON、匯入預覽。
4. 回首頁選「三種混合」，選 6 題、**15 秒**，先玩示範局，確認倒數初始為 15 秒，且新增題目可被抽中。混合模式採均衡抽題，但若某來源沒有題目，就只會由其他可用題庫抽題。
5. 重新開啟網站，確認新增題庫仍在。
6. **發布更新後的 Firebase 規則**，再用兩支手機以 **15 秒**建立並加入同一個真實房間，確認雙方題目相同，完成投票、開獎及排行榜更新。
7. 發生錯誤時截圖「遊戲畫面上的繁體中文錯誤提示」及瀏覽器 Console 錯誤訊息以排查。

## 技術細節與限制

- 部署：GitHub Pages 靜態 HTML、CSS、JavaScript。即時多人連線：Firebase Authentication 匿名登入＋Cloud Firestore。
- AI 生成：主持人自己的 Gemini 網頁，**不透過 API**，不能自動讀取 Gemini 對話，也不會定時更新題庫。
- 自訂題庫：主持人本機保存，未提供跨主持人共用的雲端題庫後台。
- 已開局的題目採房間內快照；舊版房間仍可使用原有的 `questionIds` 讀取內建題目。
- 玩家無需登入 Gemini；主持人的 Gemini 對話不會傳入 Firebase，只有**確認加入且開局抽中的題目內容**會放入房間資料。
- 既有計分方式保持不變：猜多數 +100、連勝加分、冷門得分、一次性雙倍王牌。
- 此程式適合朋友間休閒競賽，非防作弊等級的獎金比賽平台。

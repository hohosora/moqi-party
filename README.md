# 歷史更新紀錄：主持人照片功能（非本次 3.0 的更新步驟）

以下是當時新增照片功能的部署紀錄。若先前已完成 Firebase 規則發布，**本次三主題視覺更新不需要再次發布安全規則，也不需要手動上傳 ZIP**。

此更新以 `hohosora/moqi-party` 目前的《默契失控局》**三合一題庫＋Gemini 題數連動＋15／30／45 秒**版本為基礎，新增活動照片主視覺功能。網站仍使用 **GitHub Pages + Firebase Authentication + Cloud Firestore**，不需要 Gemini API、Cloud Storage 或重建 Firebase 專案。

## 新增功能

- **首頁右上角**：原本的 🤪 表情可以由主持人在首頁選照片替換。
- **照片壓縮**：在主持人瀏覽器內處理 JPG／PNG／WebP，限制原圖 **8 MB**，從中央裁成正方形、縮成小圖並轉成 JPEG。壓縮後的資料 URI 長度限制為 **40,000 字元以下**（通常不超過約 30 KB），符合本次安全規則的限制。
- **主持人本機保存**：使用瀏覽器 `localStorage` 記住壓縮後的小圖。同一裝置、同一瀏覽器再次打開網站，通常仍會保留；清除網站資料、無痕模式、換裝置可能消失。
- **同步給玩家**：主持人建立**新的多人房間**時，將小圖存入該房間的 Firestore 文件 `rooms/{房號}.heroImage`。玩家加入房間後，等候室與遊戲頁面會顯示主視覺縮圖；不必安裝 App 或登入 Google。
- **房間內修改**：主持人在**等候室**可以再次上傳照片、立即同步給已加入房間的玩家，或選擇「還原 🤪」。其他玩家不能替房間上傳／修改照片。
- **示範模式**：一樣支援主視覺圖片、還原與原本的遊戲計分。
- **相容舊房間**：舊房間若沒有 `heroImage`，仍可照原本方式遊玩。照片並不會影響題目快照、倒數計時、投票、排行榜。

## 使用者實際操作

1. 開啟 https://hohosora.github.io/moqi-party/。
2. 在首頁「📸 主持人自訂主視覺」點「📷 選擇照片」，挑選 JPG、PNG 或 WebP。
3. 網頁將照片自動置中裁成圓形展示；如果沒有滿意，繼續選另一張即可。
4. 選題庫、題數、答題秒數，按「🚀 建立多人房間」。
5. 分享 6 碼房號或邀請網址給其他玩家。其他玩家加入後就能在房間看到照片。
6. 主持人想換照片，可在等候室「更換本房間主視覺」重新上傳；若要還原，按「↩ 還原 🤪」。

> **照片只共享壓縮小圖，沒有上傳原始大檔**。但同步小圖會存入 Firestore 房間文件，知道房號、並已登入 Firebase 匿名身分的使用者有可能讀到，請勿使用敏感、私密或未經當事人同意的照片。現有規則仍是輕量聚會用途，並非防護機密資料的平台。

## 必做的更新：GitHub 檔案 + Firebase 規則

這一版與單純修改顯示秒數不同：**一定要更新 Firestore 規則**。即使 GitHub 已上傳 `firestore.rules`，**Firebase 控制台不會自動讀取並發布 GitHub 上的規則**。

### A. GitHub：更新 3 個檔案

1. 解壓縮本升級包。
2. 打開 https://github.com/hohosora/moqi-party ，確認位於 `main` 分支。
3. 點 **Add file → Upload files**，上傳壓縮包內新版 `app.js`、`styles.css`、`firestore.rules`，並可選擇更新 `README.md`。
4. 務必是**同名覆蓋儲存庫根目錄的舊檔**，不要出現 `app (1).js`、多一層資料夾、或只上傳 ZIP。
5. 點 **Commit changes**，訊息可輸入「新增主持人主視覺照片與多人同步」，選擇直接提交 `main`。
6. `index.html` 和你現在用的 `firebase-config.js` **完全不需要改**，尤其不可拿範例設定覆蓋已填的 Firebase 設定。

### B. Firebase：發布新的 Firestore Rules（必要）

1. 開啟 https://console.firebase.google.com/project/moqi-party/firestore/rules 。
2. 在 GitHub 或解壓縮資料夾中打開新版 **`firestore.rules`**，複製全部內容。
3. 在 Firebase Console → Firestore Database → **規則（Rules）**，將目前編輯區中的舊規則以新規則**完整取代**。
4. 檢查頁面沒有語法錯誤，按 **發布（Publish）**，確認發布成功。
5. 本次規則保留「僅主持人能更新房間資料」的條件，並對 `heroImage` 追加 **JPEG Data URL / 40,000 字元**的型別及長度驗證；沒有照片的舊房間仍可用。
6. 不必重新建立 Firestore、匿名登入、Firebase 網頁應用程式或專案。**Firebase Cloud Storage 不需要啟用，Spark 方案可維持**。

### C. 網站測試

1. GitHub 部署完成後，開啟 https://hohosora.github.io/moqi-party/ 。如果仍顯示舊版，Windows 按 `Ctrl + Shift + R` 強制重新整理。
2. 確認首頁出現「主持人自訂主視覺」；挑選一張照片，確認右上角 🤪 換成圓形照片。
3. 重新整理，確認在同一瀏覽器仍保留照片。
4. 按「🎭 先玩示範局」，確認等候室縮圖正常；上傳另一張照片，再按還原，確認縮圖移除、預設 🤪 恢復。
5. 回首頁再選一張照片；使用主持人手機建立**正式多人房間**。用第二支手機（或不同瀏覽器）加入，確認雙方能看到同一張主視覺。
6. 在**等候室**由主持人更換照片，確認第二支手機同步更新；按「還原 🤪」，確認兩邊縮圖不再顯示。
7. 選 15 秒、6 題，完成一題投票、揭曉和排行榜，確認原本功能正常。

## 成本與限制

此版本**不使用 Firebase Cloud Storage，也不需要付費 AI API**。圖片以小圖放在現有 Firestore 房間資料；使用 Spark 方案、在免費配額內一般不會產生額外費用。仍會占用 Firestore 文件讀寫和流量配額；超出免費限制時服務可能受到限制，並不是無限制免費的圖片代管服務。

照片不適合用於保存原始相片、用戶照片相簿或商業圖片庫；若未來想開放每個玩家上傳大圖，應改成專門的圖片存放架構並重新評估費用與隱私設計。
